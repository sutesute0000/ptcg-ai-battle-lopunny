# PTCG AI Battle Challenge — 作戦計画 (2026-08-02 起点)

## 締切
- シミュレーション部門: **2026-08-17 (月) 8:59 JST** — 残り15日
- ストラテジー部門(レポート, 賞金$30k×8): 2026-09-14

## 基本方針(ユーザー決定)
**強いデッキを軸に、そのデッキが生み出す勝ちパターンを特定し、パターンを押し付ける
エージェントを作る。** 相手の想定手のモデリングは薄くてよい(強デッキはパターンの
押し付けで勝つ)。最初から Step 3(評価関数+スコアリング)を見越した設計にする。

## 検証済みの外部知見 (reference: wmh/ptcg-abc — 公開参加者リポジトリ)
- **デッキ選択がエージェント品質を支配する。** ただしルールベースが綺麗に回せる
  「シンプルなデッキ」が実運用では勝つ(複雑コンボデッキは操縦ミスで負ける)。
- **メタの変遷が速い**(3日でトップシェアが絶滅する例あり)。デッキ決定は
  最新エピソードデータのメタ分析でやる。
- **勝ちパターンの特定方法が確立している**: Kaggleが毎日エピソードデータセット
  (実ラダー対戦の全リプレイ、トップ勢含む)を公開している。
  トップパイロットの対局を自エージェントでリプレイし、不一致(divergence)を
  カード名レベルにデコードして具体的な操縦ルールに落とす。
  = 「そのデッキの主なパターンの特定」を経験的にやる手段。
- **ローカルcabt環境はノイジーで、ラダー順位の予測は外す。** 回帰テスト用途に
  限定し、真の判定は実ラダーのA/B(1日5提出、直近2つがスコア対象)。
- エンジンAPI: `agent(obs) -> list[int]`。obs.select None時は60枚デッキIDを返す。
  SelectContext/OptionType の列挙値は reference/CLAUDE.md 参照。

## 実行ステップ
1. **[ブロック中] Kaggle認証 + ルール同意** → 公式スターター(エンジン cg-lib)、
   エピソードデータセット、リーダーボードをダウンロード
2. 直近3日ぶんのエピソードでメタ分析 → 上位アーキタイプの分布・勝率・相性を出し、
   「シンプルで強い」デッキを1つ選定(+ヘッジ1つ)
3. 選定デッキのトップパイロット(Elo上位)の全対局を抽出 → 行動パターンを
   カード名レベルで集計(何を出す/貼る/進化/攻撃をどの優先度でやるか)
4. スコアリング型エージェント実装(合法手ごとに評価点、最高点を返す。
   時間管理+合法フォールバック内蔵) → パターン集計値で優先度を調整
5. 最速で1回提出してバリデーションを通す → 以後ラダーA/Bで反復
6. 全実験ログを docs/ に記録(ストラテジー部門レポートの材料)
