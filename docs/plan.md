## Phase 1 (8/3〜8/5): 先読みの導入 ← 最優先

**根拠**: エンジンに前方シミュレーションAPI (`search_begin` / `search_step`)
があり、1回0.4msで動作することを確認済み。持ち時間は1ゲーム10分に対し、
現在の消費は1判断あたり**0.09ms**。1判断に3秒使えるので、**約7,500回の
シミュレーションが可能**なのに、いま完全に遊ばせている。

現状のエージェントは「手を見てスコアを推測する」方式。先読みは「実際に
やってみて結果の盤面を評価する」方式で、質的に上位。

1. 攻撃・にげる判断から着手(分岐が少なく効果が大きい)
   — 各合法手を1手進め、結果盤面(相手HP・自分HP・サイド差・場のエネ)を評価
2. 相手の手札/山札は不明なので予測値を渡す(自デッキは既知、相手は
   メタ分析から最有力リストを推定)
3. 時間管理を必ず入れる: 残り時間監視 + 打ち切り時は現行スコアにフォールバック
4. `engine_rate.py` と `gauntlet.py` (120戦/相手) で検証してから提出

**リスク**: 相手デッキの予測が外れるとシミュレーションが歪む。まずは
「自分の行動の直接効果」だけを見る1手先読みに限定し、相手の応手は読まない。

トップパイロットとの一致率で伸びしろが残っている領域:

- 毎日 `autopsy.py` で自分の対局を取得 → 負けた相手を特定
- `divergence.py` で該当マッチアップに絞ってルールを抽出
- **必ず `gauntlet.py` 120戦/相手で勝率を確認してから提出**

## Phase 3 (8/10〜8/14): メタ追従

メタは3日でトップデッキが入れ替わる速度で動く(実例: ミミロップは
7/30に0.2% → 8/1に21.9%)。

- 毎日 `meta_analyze.py` で分布と相性を再取得
- ミミロップが対策され始めたら**デッキ変更も選択肢**
  (判断期限は8/12。それ以降の乗り換えは調整時間が足りない)
- 苦手な Alakazam 系(構造的に35%)のシェアが伸びたら要検討

## Phase 4 (8/14〜8/17): 凍結と最終提出

- 新規の実験は8/14で打ち切り
- 最終2枠に「最良版」と「その1つ前の安定版」を置く(直近2つが採点対象)
- 提出は締切24時間前までに完了させる(検証待ちとラダー収束の時間を確保)

## Phase 5 (8/17〜9/14): ストラテジー部門レポート ← 賞金はここ

上位8チームに各$30,000。評価軸は「エージェントの安定性・デッキコンセプト・
シミュレーション部門の成績の総合」。シミュレーション順位だけでは決まらない。

**すでに手元にある強い素材**:
- 勝ちパターンをリプレイから経験的に導出した手法(divergence + 条件付き集計)
- 却下した仮説の記録(ノコッチ優先、エネルギーサーチ優先、格闘弱点ルール)
- 「エンジン発動率」というデッキ固有の内部指標を作り、勝率より信頼できる
  ことを実証した話(ローカル51% vs 実ラダー52%)
- 測定手法そのものの検証(40戦では判定不能、相手ボットの質が結果を支配)

レポートは Phase 1〜4 と並行して書き足していく。実験のたびに記録を残す。

## 正直な見通し

シミュレーション部門で上位8位(=レポート部門の第2ラウンド進出)は、
現在5,000位からでは厳しい。ただしレポート部門の評価はシミュレーション成績
「のみ」ではないため、**方法論の質で勝負する価値はある**。

Phase 1 の先読みが最大の勝負どころ。ここで大きく伸びなければ、
リソースをレポートの質に寄せる判断も検討する(判断時期: 8/10頃)。

## 遵守事項(ここまでで痛い目を見た点)

1. 比較したい2択が**両方選べた場面**に絞って集計する
2. 行動の「回数」は優先「順位」ではない
3. **1相手40戦では判定できない**(同条件で92%→82%と振れた)。最低120戦
4. 相手ボットの質が結果を支配する。汎用ボットの数字は上限値
5. エンジン発動率は必要条件であって十分条件ではない(上げても勝率が
   上がらない例を確認済み)
6. 合法手以外を返さない / ネットワーク・外部API・実行時LLM呼び出しは禁止
